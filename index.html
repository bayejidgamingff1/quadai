How to use the QUAD API

Integrate QUAD AI into your app, website, or backend.

1. Request API access

Contact BAYEJID to request developer access and receive an API key with the required chat:use permission. Keep your API key private.

2. API endpoint

Method: POST
Endpoint: https://bayejidai.vercel.app/api/v1/chat

curl -X POST "https://bayejidai.vercel.app/api/v1/chat" \ -H "Content-Type: application/json" \ -H "Authorization: Bearer YOUR_API_KEY" \ -d '{"message":"Hello QUAD AI"}'

3. Use it in JavaScript (server-side)

Save the API key as an environment variable named QUAD_API_KEY. Never put a real secret in browser JavaScript or a public GitHub repository.

const response = await fetch( "https://bayejidai.vercel.app/api/v1/chat", { method: "POST", headers: { "Content-Type": "application/json", "Authorization": `Bearer ${process.env.QUAD_API_KEY}` }, body: JSON.stringify({ message: "Hello QUAD AI" }) } ); const result = await response.json(); console.log(result);

4. Deploy your own QUAD AI website on Vercel

  1. Create a new GitHub repository for your website.
  2. Add the site files, including index.html and the api/chat.js serverless function included with this starter project.
  3. Import the repository into Vercel and deploy it.
  4. In Vercel, open Project → Settings → Environment Variables.
  5. Add QUAD_API_KEY as the variable name and paste your private API key as its value. Select the environments you need, save, then redeploy.
  6. Open the deployed URL and test the chat.
Important: The included chat uses a server-side proxy so the secret key is not sent to visitors' browsers. Do not hard-code the API key into index.html.

5. Common errors

  • 401 UNAUTHENTICATED — check that the key is correct, active, and sent in the Bearer header.
  • 403 INSUFFICIENT_SCOPE — ask BAYEJID to enable the chat:use scope for your key.
  • 429 — you may have reached a rate limit or quota; try later or contact the API owner.
  • 500 or network error — check the deployment logs and API status.
